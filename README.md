## 📱 About

**CampusCart** is a Flutter-based mobile marketplace app designed for university students in Rwanda. It enables students to safely buy and sell items like textbooks, clothes, electronics, and furniture within their campus community.

The app addresses real friction points identified during field research:
- Price inconsistency on WhatsApp listings
- Misleading stock/AI-generated product photos
- Lack of seller verification
- Disorganized, inefficient search on existing channels

## 🚀 Running the App

### Prerequisites
- Flutter SDK installed (3.x)
- Chrome browser (for web demo)
- VS Code or Android Studio

### Steps
```bash
# Clone the repo
git clone <repo-url>
cd progressive-capstone-project-devdynasty/campuscart

# Install dependencies
flutter pub get

# Run on Chrome
flutter run -d chrome
```

### Running individual Part A demos
```bash
dart run lib/dart_basics/variables_demo.dart
dart run lib/dart_basics/collections_demo.dart
dart run lib/dart_basics/functions_demo.dart
```

### Running Part B integrated demo
```bash
dart run lib/part_b_demo.dart
```

### Building the release APK (Phase 10)
```bash
cd campuscart
flutter pub get

# one-time, generates the launcher icon and splash screen
dart run flutter_launcher_icons
dart run flutter_native_splash:create

# build the installable Android APK
flutter build apk --release
```
The finished APK is written to:
`build/app/outputs/flutter-apk/app-release.apk`

## 🧠 Key Concepts Demonstrated

### Part A — Dart Fundamentals
- Type-safe variables (`String`, `int`, `double`, `bool`)
- Null safety operators (`?`, `!`, `??`, `??=`, `?.`)
- Collections: `List`, `Map`, `Set`
- Functions: arrow, named parameters, optional params, higher-order

### Part B — OOP & Data Models
- Base class `User` with `Seller` and `Buyer` extending it (inheritance)
- `Rateable` and `Timestamped` mixins for shared behavior
- `Product` class combining both mixins (`with Rateable, Timestamped`)
- `ProductService` with `async`/`await` to simulate network calls

### Part C — Flutter UI
- Material Design 3 theme (seeded color scheme)
- Custom reusable widgets (`ProductCard`, `CategoryChip`)
- `StatefulWidget` for dynamic state (search, filter, loading)
- Responsive layouts with `Column`, `Row`, `ListView`, `Expanded`

### Part D — Navigation & Forms
- Named routes declared in `MaterialApp.routes`
- Data passing via `Navigator.pushNamed(..., arguments: ...)`
- Returning results via `Navigator.pop(context, true)`
- Form validation with `GlobalKey<FormState>` and field validators
- Live validation with `AutovalidateMode.onUserInteraction`

## 🚧 Progressive Capstone — Phase-by-Phase Overview

The Mini-Capstone (Parts A–D) is the foundation. The app was then
extended, one phase at a time, into a full cloud-connected
marketplace. Each phase below is a single Git commit.

| Phase | Feature | Status |
|-------|---------|--------|
| 1 | Login, Sign Up & Profile screens | ✅ Done |
| 2 | State management with Provider | ✅ Done |
| 3 | Local database (Hive) | ✅ Done |
| 4 | Image upload (gallery + camera) | ✅ Done |
| 5 | Favorites + advanced search/filters | ✅ Done |
| 6 | Firebase Authentication | ✅ Done |
| 7 | Firebase Firestore (cloud database) | ✅ Done |
| 8 | Firebase Storage (cloud image uploads) | ✅ Done |
| 9 | Real-time chat between buyers & sellers | ✅ Done |
| 10 | Polish, app icon, build APK | ✅ Done |

### Phase 1 — Complete the Missing Screens

Added the Login, Sign Up, and Profile screens so the app has a
full screen flow. All built with form validation and named-route
navigation, no backend yet.

### Phase 2 — State Management with Provider

Replaced scattered per-screen state with the `provider` package.
Introduced `ProductProvider` and `UserProvider` as single sources
of truth; every screen now reads shared state and refreshes
automatically.

### Phase 3 — Local Database (Hive)

Products are persisted on the device with the `hive` package, so
data survives app restarts. Full CRUD (create, read, update,
delete) through a `ProductDatabase` helper.

### Phase 4 — Image Upload

Real product photos via the `image_picker` package — choose from
gallery or take a photo with the camera. Includes native camera
permission handling for Android, iOS, and macOS.

### Phase 5 — Favorites & Advanced Search

A heart button to favorite products and a "My Favorites" screen
(favorites stored locally in Hive). Advanced filtering by price
range and condition, plus sort options (newest, price, A–Z).

### Phase 6 — Firebase Authentication

Replaced the simulated login with **real Firebase Auth** — real
email/password accounts, "stay logged in" across restarts,
friendly error messages, and password-reset emails.
- `lib/services/auth_service.dart` — wraps Firebase Auth
- `lib/providers/user_provider.dart` — Firebase-backed, listens
  to `authStateChanges()`
- **Setup:** create a Firebase project, enable Email/Password
  sign-in, run `flutterfire configure`.

### Phase 7 — Firebase Firestore

Products moved from local-only Hive to **Cloud Firestore**, so
listings sync across devices in real time via a live stream.
- `lib/services/product_firestore_service.dart` — Firestore CRUD
- `ProductProvider` subscribes to a real-time product stream
- **Setup:** enable Firestore in the Firebase console.

### Phase 8 — Firebase Storage

Product photos are uploaded to **Firebase Storage** instead of
being stored as raw bytes inside Firestore documents (which have
a 1 MB limit). Firestore now keeps only a small image URL.
- `lib/services/storage_service.dart` — wraps Firebase Storage
- `addProductWithImage()` in `ProductProvider` — uploads the
  photo, then saves the product
- Images display via `Image.network` from the Storage URL, with
  a fallback to a category icon
- **Setup:** in the Firebase console, **Build → Storage → Get
  started** (test mode is fine for the demo), then
  `flutter pub get`. No `flutterfire configure` needed again.

### Phase 9 — Real-time Chat

Buyers can message sellers about a product, with messages syncing
**instantly** via Cloud Firestore. A Messages inbox lists every
conversation.
- `lib/models/chat_message.dart` — message model
- `lib/services/chat_service.dart` — Firestore chat wrapper
- `lib/screens/conversation_screen.dart` — the live chat thread
- `lib/screens/messages_screen.dart` — the conversation inbox
- The "Chat Seller" button on product details now opens a real
  conversation
- **Setup:** none — chat reuses Firestore from Phase 7. Testing
  needs two accounts (run in two windows or as different users).

### Phase 10 — Polish & APK

Final polish to make the app feel finished:
- **App icon** — a custom teal shopping-cart launcher icon,
  generated for Android, iOS, and web via `flutter_launcher_icons`
  (source art in `assets/icon/`).
- **Splash screen** — a native splash in the brand teal via
  `flutter_native_splash`.
- **Animations** — product cards fade and slide in on the home
  list (`FadeIn` widget); tapping a product runs a smooth Hero
  shared-element transition on its image into the details screen.
- **Naming** — the app now displays as "CampusCart".
- **Setup:** after `flutter pub get`, run once:
  `dart run flutter_launcher_icons` and
  `dart run flutter_native_splash:create`.
- **Release build:** `flutter build apk --release` produces the
  installable APK at
  `build/app/outputs/flutter-apk/app-release.apk`.
